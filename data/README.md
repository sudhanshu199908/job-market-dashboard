# postings_clean.csv — data dictionary & parse coverage

Structured extraction from Sudhanshu Dhankhar's verified job-application ledger
(`~/workspace/job_hunt/applied.json`), covering applications logged
**6–15 October 2026** across LinkedIn, Naukri, Instahyre, Shine, Internshala,
Foundit, email/direct applications, a Rohtak desk-job round, and a remote
non-voice support/writing stream. Generated by
`../analysis/01_parse_ledger.py` — re-run it to rebuild this file.

## Columns

| column | meaning |
|---|---|
| `entry_id` | `{portal}_{i}` — stable row id within the source list |
| `portal` | source list: `linkedin`, `naukri`, `instahyre`, `shine`, `email`, `foundit`, `rohtak`, `internshala`, `direct`, or `support_linkedin` / `support_naukri` / `support_other` |
| `stream` | `analyst` (Data/BI/MIS roles) or `support` (non-voice support & writing roles) |
| `company` | hiring company, best-effort (empty when not identifiable) |
| `title` | job title, best-effort, normalised (empty when not identifiable) |
| `city` | canonical city (`Gurugram`, `Noida`, `Delhi`, `Bengaluru`, `Mumbai`, …), `Remote (unspecified)` when remote with no city, else `unknown` |
| `work_mode` | `remote` / `hybrid` / `on-site` / `unknown` |
| `salary_min_lpa`, `salary_max_lpa` | salary band normalised to ₹ LPA (empty when undisclosed or unparseable) |
| `salary_raw` | the literal salary text found |
| `salary_note` | `usd-annual-converted` (×₹83), `monthly-converted` (×12), `hourly-rate-excluded`, `per-task-rate-excluded`, else empty |
| `exp_min`, `exp_max` | experience band in years (empty when not stated) |
| `date_applied` | `YYYY-MM-DD` of application (empty when the ledger note carries no date) |
| `job_id` | `li_<id>` / `nk_<id>` when a posting id was present |
| `url` | posting URL when present |
| `skills` | `;`-separated skill keywords found in the ledger note (see caveat) |
| `raw` | the original ledger entry, verbatim (audit trail) |

43 early LinkedIn entries and 24 early Naukri entries are bare URLs with no
notes (LinkedIn URLs carry no metadata at all); Naukri slugs still yield
location + experience. These rows contribute to counts but are excluded from
field-specific charts — every chart labels its own `n`.

## Honest caveats

- **Salaries are thin (n=84).** Most postings in the ledger don't disclose pay;
  the distribution reflects only disclosing postings, which skews toward
  staffing firms and startups.
- **Hourly/contract rates are excluded** from LPA charts (9 postings, e.g.
  `$60/hr`, `$11/hr`, `$15/task`) — annualising them would distort the scale.
  One USD-annual band (`$42,000–$68,000` → 34.9–56.4 LPA) is included but was
  flagged as suspicious in the ledger itself (looks like a US band pasted on an
  India-remote listing).
- **Skills come from ledger notes, not full job descriptions** (n=93). Counts
  reflect what was recorded while applying (titles, screening questions), so
  they undercount true demand — treat as directional, not exhaustive.
- **The candidate's own screening answers were stripped** before parsing
  (e.g. `(answers: 3 LPA current, 7 LPA expected…)`, `SQL=1yr`), so salary and
  experience figures are the postings' requirements, never his answers.
- **Work mode is unknown for 45% of postings** — the ledger often omits it.
- A handful of postings appear in both an applied list and a skipped list
  (applied after an initial skip); no duplicates exist *within* applied lists.

## Public-release note
The `raw` notes column is redacted for public sharing: personal email addresses and phone numbers are replaced with `[email redacted]` / `[phone redacted]`, and internal review flags were removed. All analytical columns are untouched.
